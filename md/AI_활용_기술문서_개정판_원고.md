# 《미기록 구역》 AI 활용 기술 문서 개정판

## 1. 프로젝트와 AI 활용 목표

《미기록 구역》은 제어실에서 CCTV 영상을 감시하고, 평소와 달라진 이상현상을 `구역 + 대상 + 유형`으로 보고하는 2D 심리 공포게임이다. CCTV의 작은 화면에서도 변화가 읽혀야 하고, 같은 공간을 반복해서 보면서도 불안이 유지되어야 하므로 기획·아트·개발이 같은 가독성과 공포 기준을 공유해야 했다.

생성형 AI는 완성품을 대신 결정하는 도구가 아니라 **아이디어 탐색, 제작 공정 설계, 구현 명세화와 연관 데이터 QA를 연결하는 협업 도구**로 사용했다. AI가 제안한 이미지·문서·코드는 담당자가 직접 선택·수정·검증했으며, 게임의 정답과 실패 조건은 실시간 생성형 출력이 아닌 결정적 데이터로 판정한다.

### 한눈에 보는 활용 범위

| 영역 | AI 활용 | 담당자의 최종 책임 |
| --- | --- | --- |
| 기획 | 플레이 구조 대안 비교, 공포 규칙 검토, 시나리오 인과관계와 콘텐츠 후보 구조화 | 재미·범위 결정, 아이디어 채택·삭제, 스토리와 콘텐츠 승인 |
| 아트 | 이미지 시안 생성, 반복형 배경 공정 탐색, 프랍 제작 조건과 후가공 체크리스트 정리 | 시안 선택, 요소 분리, 리터칭, 색 보정, 애니메이션과 Unity 배치 |
| 개발 | 저장소·씬·프리팹·데이터 분석, 구현 초안, 상태 충돌 추적, 이미지·로그 기반 디버깅 | 게임 규칙 확정, 코드 리뷰, Inspector 연결, 빌드·플레이 검증 |
| 통합·QA | MD 문맥 요약, 문서 비교, 변경 영향 범위와 ID 재검색 체크리스트 생성 | 원본 수정, Git 이력 승인, 인수인계와 완료 판단 |

> **활용 원칙:** AI 생성 → 담당자 검토 → 문제 재정의 → AI 대안·수정 → 담당자 최종 결정

## 2. 파트별 역할, 도입 효과와 활용 도구

### AI 도입 전·후 효과 비교

| 구분 | 기존 수작업 방식 | AI 파이프라인 적용 후 |
| --- | --- | --- |
| 비주얼 방향 결정 | 레퍼런스 조사와 초기 시안 작성에 긴 시간 필요 | 짧은 시간에 여러 시안을 비교해 스타일 탐색 폭과 의사결정 속도 향상 |
| 배경 제작 공정 설계 | 반복형 배경 경험이 부족해 벽·바닥 연결과 작업 순서에서 시행착오 발생 | LLM에 횡스크롤 구조, 일정, 인원, 가독성 조건을 입력해 제작 순서와 우선순위 확정 |
| 에셋 제작 | 타일·배경·프랍을 모두 개별 제작 | 컨셉아트 생성 → 요소 분리 → 사람의 리터칭으로 계획 리소스 범위 확보 |
| 게임 적용·검증 | 에셋 배치 후 코드·데이터 연결을 수동 추적 | Codex로 프리팹 ID·이상현상 정의·표현 액션을 교차 검사해 반복 작업 단축 |

> **심리스 타일(Seamless Tile):** 같은 벽·바닥 이미지를 반복 배치해도 연결 경계가 보이지 않도록 만든 반복형 텍스처이다. AI 기술명이 아니라 긴 횡스크롤 배경을 효율적으로 구성하는 그래픽 제작 방식이다.

### 활용 도구와 선정 이유

| 도구 | 주 사용 파트 | 활용 내용 | 결과 |
| --- | --- | --- | --- |
| ChatGPT 이미지 생성 | 아트 | 공포 분위기, 공간 용도, 색감, 구도와 프랍 조건을 반영한 시안 생성 | 배경 시안, 키 비주얼, 프랍 초안 |
| Gemini | 아트·기획 | 프로젝트 제약을 입력해 공정 순서와 대안 비교 | 반복형 배경 공정, 제작 우선순위와 절충안 |
| OpenAI Codex | 개발·통합 | PRD, Unity 에셋, C# 코드, 로그와 데이터 분석·수정 | 시스템 구현, 데이터 QA, 디버깅과 문서화 |
| Unity·Git·Sheets | 전체 | 실제 배치·플레이 검증, 변경 이력, ID 기반 데이터 관리 | 화면 가독성 확인, 회귀 관리, 연관 데이터 재검증 |

출시 빌드에서는 생성형 AI API를 실시간 호출하지 않는다. 게임에 포함되는 결과물은 담당자가 검수하고 확정한 정적 에셋과 로직이다.

## [아트] 3. AI 파이프라인과 제작 역할

아트 파트는 생성 이미지를 완성품으로 간주하지 않고, 탐색 속도는 AI로 높이되 최종 형태와 게임 가독성은 사람이 통제하도록 역할을 분리했다.

### 3단계 제작 파이프라인

| AI 탐색 | 아티스트 제작 | 개발·검증 |
| --- | --- | --- |
| ChatGPT 이미지 시안 생성<br/>Gemini 제작 공정 비교 | 시안 선택<br/>요소 분리·리터칭·색 보정 | Unity 배치<br/>Codex 데이터 교차 검사<br/>CCTV 플레이 테스트 |

AI는 비주얼 후보와 제작 공정의 탐색 속도를 높였다. 최종 에셋의 선택, 분리, 리터칭과 색 보정은 아티스트가 수행했으며, 실제 CCTV 화면의 가독성과 게임 동작은 개발자가 Unity에서 검증했다.

### AI 활용 기술 중심 구현 사례

| AI 활용 기술 | 적용 방식 | 사람의 판단·후처리 | 얻은 효과 |
| --- | --- | --- | --- |
| 생성형 이미지 기반 비주얼 탐색 | 공포, 폐쇄감, 노후 시설, CCTV 색감 조건으로 배경과 키 비주얼 시안 생성 | 무드·팔레트·구도·오브젝트 밀도 비교 후 방향 선택 | 언어로 합의하기 어려운 분위기를 빠르게 시각화 |
| LLM 기반 심리스 타일 공정 설계 | 횡스크롤, 소수 인원, 짧은 일정, 관찰 가독성을 입력해 벽·바닥 반복 단위와 우선순위 설계 | 연결부, 오염·파손 변주와 공간별 구획 요소 제작 | 공통 배경을 재사용하면서 여러 CCTV 공간의 차이 확보 |
| 컨셉아트 요소 분리·프랍 에셋화 | 시안에서 벽·바닥·문·전화기·침대·휠체어·액자 등의 분리 기준 정리 | 투명 영역, 윤곽, 색상, 명암, 픽셀 밀도와 원근 보정 | 정상·이상 상태 교체가 가능한 독립 프랍 확보 |

## [아트] 4. 제작 명세, 프롬프트와 품질 검증

### 제작 가능한 이미지 명세로 변환

아트 프롬프트에는 분위기만 쓰지 않고 화면 규격과 게임 조건을 함께 넣었다. 5760×900 횡스크롤 배경, 완전한 측면 시점, 수평 바닥, 하단 이동 공간, 고정 건축 요소와 이상현상 프랍의 분리, 낮은 채도의 회녹색·청록 계열을 제작 기준으로 정리했다.

| 목적 | 프롬프트에 넣은 조건 | 사람이 수행한 작업 | 실제 적용 |
| --- | --- | --- | --- |
| 배경 시안 | 폐쇄된 의료·연구시설, 고정 측면 구도, CCTV 색감 | 화면 비율, 조도, 오브젝트 밀도 선택 | 배경 무드와 키 비주얼 확정 |
| 반복형 배경 | 짧은 일정, 벽·바닥 재사용, 공간별 변주 | 연결 흔적 제거, 오염·파손과 구획 프랍 제작 | 심리스 타일 기반 배경 구성 |
| 정상·이상 프랍 | 크기·앵커 동일, 실루엣 차이, 축소 화면 가독성 | 윤곽·명암·노이즈·투명 영역 리터칭 | 문·시계·액자·침대 등의 변형 에셋 |
| 애니메이션 | 프레임 수, 반복 여부, 마지막 프레임 유지 | 기준 프레임과 피벗 정렬, 픽셀 흔들림 수정 | 인물·커튼·침대 연출의 일관성 개선 |

### 품질 검증과 한계 대응

- **프레임 일관성:** 생성 이미지의 머리·상체·발 위치와 의상 형태가 달라지는 문제를 기준 프레임과 피벗 정렬로 보정했다.
- **경계·해상도:** 잘린 경계, 배경 잔여 픽셀, 색과 픽셀 밀도 차이를 필수 후가공 항목으로 관리했다.
- **관찰 공정성:** CCTV 셰이더, 카메라 이동과 보고 UI가 겹친 실제 화면에서도 변화가 인지되는지 플레이 테스트했다.
- **저작권·책임:** 특정 작가의 고유 스타일 대신 분위기·시대감·색감·재질 조건을 사용하고, 생성 결과는 제작 초안으로만 취급했다.

팀 내부 추산으로 컨셉아트의 프랍 초안을 재구성·리터칭하는 방식은 모든 소품을 처음부터 그리는 방식보다 원화 탐색과 초안 제작 시간을 절반 이상 줄였다. 이는 자동 완성 비율이 아니라 **초안 확보와 탐색 시간의 절감 효과**이며, 실제 게임용 마감은 아티스트가 수행했다.

## [개발] 5. Codex 기반 시스템 구현과 검증

개발 파트는 AI를 기획을 대신 결정하는 도구가 아니라, 복수 문서와 Unity 저장소의 연결 관계를 분석하고 구현·검증을 보조하는 코딩 에이전트로 사용했다.

| 개발 기능 | AI 활용 | 개발자의 최종 작업 | 결과 |
| --- | --- | --- | --- |
| 문서·데이터 정합성 | PRD, 시나리오, 콘텐츠표, `DayDefinition`, 프리팹 ID 교차 분석 | 핵심 루프와 실제 구현 범위 확정 | 문서와 Unity 데이터의 용어·수치 차이 감소 |
| 데이터 파이프라인 | `AnomalyDefinition`, `CCTVSceneObject`, 보고 유형과 기본 활성 상태 검사 | CSV→ScriptableObject 임포터와 Day 폴더 구조 검증 | 누락 타겟과 잘못된 ID·보고값 탐지 |
| 상태 흐름 | 정전, 미보고, 보고판, 카메라 전환, 입력 잠금의 충돌 순서 분석 | 상태 이벤트, 유예 시간과 입력 잠금 구현 | 중복 연출과 전환 중 입력 충돌 감소 |
| 현장 상호작용 | 배전반 조작을 범위 진입, E 안내, 홀드, 감소, 완료로 분해 | 코드 작성, Inspector 연결, 플레이 검증 | 재사용 가능한 클릭·홀드 구조 확보 |
| 이미지·로그 디버깅 | 스크린샷, 로그, 씬·코드 비교로 원인 후보 추적 | UI·셰이더·카메라 연결과 빌드 설정 수정 | 에디터·빌드 차이와 화면 오류 해결 |

### 실제 구현 흐름

> PRD·시나리오·콘텐츠표 분석 → 상태와 데이터 구조 제안 → 개발자 선택·수정 → C# 구현 → Inspector 연결 → 빌드·플레이 테스트 → Git diff와 회귀 검토

Day 1 정전과 배전반 복구, Day 2 커튼 뒤 손·얼굴·침대 아래 인물, Day 3 서버실 기록 복구처럼 기획 문서의 사건을 상태 이벤트와 데이터로 연결했다. 완료되지 않았거나 플레이로 확인하지 못한 기능은 완료로 표현하지 않고 후속 검증 항목으로 분리했다.

## [기획] 6. 프롬프트를 통한 핵심 기능 고도화

기획 파트는 많은 아이디어를 나열하는 데서 끝내지 않고, 게임의 핵심 기능별로 플레이 가독성·공정성·제작비와 서사 역할을 비교해 실제 제작 가능한 안으로 수렴시켰다.

| 핵심 기능 | 프롬프트의 판단 조건 | 고도화된 내용 | 실제 산출물 |
| --- | --- | --- | --- |
| CCTV 관찰·보고 | 정상 상태 기억, 축소 화면 가독성, 불공정한 힌트 방지 | `관찰 → 차이 발견 → 구역·대상·유형 보고 → 정상화` 루프와 노이즈 규칙 | 핵심 시스템 규칙, 보고 데이터 |
| 현장이동 | A/D 이동, 조명 조사, E 클릭·홀드, Day별 학습 단계 | 판정 중심 CCTV와 분리된 직접 공포·스토리 모드 | Day 1 배전반, Day 2 기록 확대, Day 3 서버 복구 |
| 시나리오 | 게임 규칙이 서사 의미를 갖고, Day마다 설정을 남발하지 않을 것 | “정상성은 발견되는 것이 아니라 지정된다”는 주제와 E-07·O-06·M0의 인과관계 | 시나리오 바이블과 Day별 서사 |
| 이상현상·공포 | 가독성, 중복, 제작비, 보고 공정성 | 보고형 이상현상과 일시 공포 분리, 작은 동작을 큰 실루엣 변화로 수정 | Day별 이상현상·미보고·현장이동 콘텐츠 |
| 디자인 리소스 | 정상·이상 차이, 크기·앵커, 이미지 수, 애니메이션 여부 | 추상적 아이디어를 제작자가 바로 그릴 수 있는 형태 설명으로 변환 | 디자이너 프랍 목록과 스프라이트 명세 |

## [기획] 7. 프롬프트 설계 역량과 대표 개선 사례

### 제약 조건형 프롬프트 설계

《미기록 구역》의 프롬프트는 단순히 “아이디어를 만들어 달라”고 요청하지 않았다. 게임 시점, 해상도, 핵심 규칙, 제한된 제작 범위, CCTV 축소 화면의 가독성, 제작 비용, 출력 형식과 검수 기준을 하나의 요청 안에 함께 설계했다. AI 답변을 일회성 아이디어가 아니라 기획 문서, 아트 명세, 구현 데이터와 QA 체크리스트로 이어지는 반복 가능한 작업 단위로 변환한 것이다.

| 설계 요소 | 실제 입력 내용 | 역할 |
| --- | --- | --- |
| 맥락 | 2D 횡스크롤 CCTV 감시형 심리 공포게임 | 장르와 화면 조건 고정 |
| 제약 | 1인 개발, 고정 시점, 작은 CCTV 화면, 제한된 리소스 | 과도한 기능과 제작비 억제 |

| 출력 형식 | 규칙, Day, ID, Action, 에셋, 애니메이션 여부 | 문서와 데이터로 바로 전환 |
| 재검증 | 연관 탭·프리팹·데이터에서 이전 값 재검색 | 수정 누락과 불일치 방지 |

> 생성형 AI에 정답을 요구한 것이 아니라, 프로젝트의 제약·평가 기준·출력 형식·검수 절차를 프롬프트에 설계해 아이디어를 실제 제작 가능한 사양으로 수렴시켰다.

## [통합·QA] 8. AI 시대의 MD 기반 문맥 관리와 인수인계

### 왜 MD로 정리했는가

생성형 AI 협업에서는 모델에게 전달되는 **문맥의 품질**이 결과의 일관성을 좌우한다. 채팅 기록만 남기면 최종 결정, 제외된 안, 변경 이유와 연관 데이터가 섞여 다음 작업자나 다른 AI가 같은 판단 기준을 재현하기 어렵다.

대화 결과를 Markdown 문서로 요약해 목표, 제약, 결정 사항, 변경 이유, 파일·콘텐츠 ID와 후속 검증 항목을 함께 기록했다. Markdown은 사람이 읽기 쉽고 Git에서 변경점을 비교할 수 있으며, 다른 AI 도구에도 구조화된 문맥으로 전달할 수 있다. 이 문서는 단순 회의록이 아니라 **사람과 AI가 공유하는 작업 명세이자 결정 기록**으로 사용했다.

### 실제 개발 적용 흐름

1. 기획자가 목표, 게임 규칙, 제작 제약과 문제 사례를 AI에 전달한다.
2. AI가 대안과 위험 요소를 제안하고, 담당자가 채택·삭제와 우선순위를 결정한다.
3. 결정 내용과 변경 이유를 PRD, 시나리오 바이블, 현장이동 정의서 등의 MD로 요약한다.
4. MD를 기준으로 아트 제작 명세, Google Sheets 콘텐츠 ID와 Unity 구현 항목을 갱신한다.
5. Codex가 같은 ID의 문서·데이터·프리팹 후보를 찾아 수정 범위와 QA 체크리스트를 제시한다.
6. 아티스트와 개발자가 원본을 수정하고 Unity 실제 화면과 동작을 검증한다.
7. 최종 변경과 검증 결과를 Git diff, 날짜별 기록과 인수인계 문서에 남긴다.

### 실제 활용 사례

- 일반 CCTV 이상현상에는 스토리 단서를 넣지 않고, 현장이동 메인 이벤트에서만 서사를 전달한다는 원칙을 MD에 고정했다.
- Day 1 배전반 복구, Day 2 훼손 기록 확대 관찰, Day 3 서버 기록 복구를 현장이동 공통 구조와 함께 인수인계했다.
- D2_A11 변경 시 이상현상명, 보고 대상, Action, 스프라이트, 애니메이션, Day Schedule과 프랍 명세를 같은 ID로 재검색했다.

> AI 대화를 일회성 채팅으로 소비하지 않고, 결정 이유와 제작 제약을 MD 명세로 축적해 기획·아트·개발이 동일한 문맥을 재사용할 수 있는 협업 체계를 만들었다.

## 9. 성과, 책임 분리와 안전장치

### 성과와 검증

- 제한된 일정에서도 통일된 공포 분위기와 여러 CCTV 공간의 시각적 변주를 확보했다.
- 생성 초안을 프랍 단위로 재구성해 확보한 시간을 리터칭과 게임 적용에 집중했다.
- PRD부터 씬·코드·ScriptableObject·프리팹까지 연결 관계를 추적해 아트가 실제 이상현상으로 동작하도록 검증했다.
- C# 빌드, Git diff와 Unity 플레이 테스트를 조합해 잘못된 제안과 회귀 위험을 관리했다.
- Google Sheets 8개 관리 탭과 Unity ID 체계를 연결해 보고값·Action·Schedule·프랍 명세의 동시 수정 여부를 추적했다.
- D2_A11처럼 화면 가독성이 낮은 초기안을 제작 가능한 정적 변형으로 재설계해 실제 구현 품질을 개선했다.

### 책임 분리

| 주체 | 책임 |
| --- | --- |
| AI | 시각 시안, 공정 가이드, 구조 분석, 구현 초안, 반복 수정, 정적 검사와 문서화 지원 |
| 아티스트 | 비주얼 목표와 최종 시안 선택, 분리·리터칭·색 보정·애니메이션 일관성과 Unity 배치 |

### 안전장치와 제출 전 확인

- 완료되지 않은 기능은 완료로 표현하지 않고 미확인 항목을 후속 검증으로 분리한다.
- 플레이어 개인정보나 플레이 데이터를 외부 생성형 AI API로 전송하지 않는다.
- 생성 결과는 최종본이 아닌 제작 초안으로 취급하고 사람의 선택·수정·검수를 기록한다.
- 사용 모델, 생성·후가공 범위와 생성물 규정을 공모전 제출 기준에 맞춰 확인한다.
- 대표 생성 시안과 최종 리터칭 결과, 심리스 타일 분리 과정, Unity 적용 화면은 별도 증빙으로 첨부한다.
