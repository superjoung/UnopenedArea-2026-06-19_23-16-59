# Day 1 UI·이펙트 인수인계

작성일: 2026-07-25  
담당 분리: 시스템·콘텐츠 — 프로그래머 / UI·이펙트 — 동료

## 1. 현재 Day 1 플레이 흐름

```text
브리핑
→ 기준 상태 확인
→ CCTV 감시·보고
→ 정전 발생
→ 현장 이동
→ 배전반 복구
→ 제어실 복귀 문
→ CCTV 감시 재개
→ 근무 종료·평가 (미구현)
```

현장 이동 중에는 근무 시간, 이상현상 생성, 미보고 타이머가 멈춘다. 배전반만 고쳐서는 감시가 재개되지 않으며, 제어실 복귀 문을 통해 CCTV 화면으로 돌아온 뒤에만 재개된다.

## 2. UI·이펙트 담당 범위

### P0 — 이번에 바로 필요한 작업

1. 정전 진입 연출
   - CCTV 화면을 짧게 붕괴/노이즈 처리한 뒤 암전한다.
   - 현장 카메라가 켜지는 첫 프레임을 가리지 않도록 0.3~0.8초 내외의 짧은 전환을 권장한다.

2. 현장 상호작용 안내
   - 배전반 근처: `E 길게 눌러 전력 복구`
   - 제어실 문 근처, 배전반 복구 후: `E 제어실로 복귀`
   - E 유지 게이지는 배전반에만 필요하다. 기본 유지 시간은 1.5초다.

3. 제어실 복귀 연출
   - 문 상호작용 뒤 암전 또는 CRT 노이즈를 넣는다.
   - CCTV 재가동음, 짧은 전력 복구 플래시, CCTV UI 재등장을 순서대로 구성한다.
   - 시스템은 이미 CCTV 카메라·UI·전역광을 복원한다. UI는 시각 연출만 담당한다.

4. 감시 상태 UI
   - 상단 상태: 브리핑 / 기준 확인 / 감시 중 / 정전 / 현장 복구 / 제어실 복귀
   - 목표 문구: 현재 플레이어가 해야 할 행동 한 줄
   - 결과 피드백: 정답 보고 / 오보고 / 미보고

### P1 — Day 1 완결용 작업

- 근무 종료 결과 패널: 정확 보고, 오보고, 미보고, 생존 여부.
- 정전 전환·복귀 사운드와 UI 노이즈 프로필 정리.
- 성공 보고 노이즈, 오보고 노이즈, 미보고 노이즈의 시각 언어 분리.
- 현장 복귀 후 CCTV 화면에 남길 작은 변화 또는 공포 연출.

## 3. 씬에서 연결할 컴포넌트

### `Day1FlowStatusUI`

`CCTVSceneUI`와 별개로, 항상 활성화된 Canvas 자식에 붙인다. 정전 오버레이 자체에 붙이면 오버레이가 꺼질 때 스크립트도 꺼질 수 있다.

Inspector 연결 필드:

| 필드 | 연결 대상 | 역할 |
|---|---|---|
| `Status Text` | TMP 텍스트 | 현재 상태 표시 |
| `Objective Text` | TMP 텍스트 | 현재 목표 표시 |
| `Feedback Text` | TMP 텍스트 | 정답/오답/미보고 짧은 피드백 |
| `Emergency Overlay` | 정전용 패널 | 정전 상태 표시 |
| `Primary Action Root` | 버튼 오브젝트 | 브리핑/감시 시작용 임시 버튼 |
| `Primary Action Label` | 버튼 TMP 텍스트 | 버튼 문구 |

`Primary Action Root`는 브리핑/기준 확인 단계의 임시 진행 버튼이다. 현장에서는 배전반·문 상호작용을 사용하므로 별도 버튼을 만들 필요가 없다.

### `FieldBreakerPanel`

배전반 오브젝트에 붙인다.

- 기본 반경: 1.5
- 기본 입력: `E`
- 기본 유지 시간: 1.5초, Inspector에서 1~2초로 조절 가능
- 완료 시 시스템이 `EmergencyRecovery` 상태로 바꾸며, 감시 루프는 아직 재개하지 않는다.

### `FieldControlRoomDoor`

현장 맵의 제어실 복귀 문 또는 귀환 지점에 붙인다.

- 기본 반경: 1.5
- 기본 입력: `E`
- 기본 유지 시간: 0.35초
- 배전반 복구 전에는 작동하지 않는다.
- 완료 시 CCTV 카메라/UI/조명을 되살리고, 그 뒤 감시 타이머와 이상현상 생성을 재개한다.

## 4. UI가 구독하거나 호출할 수 있는 시스템 연결점

### 구독용 이벤트

`Day1FlowController`

- `StateChanged(Day1FlowState)` — 상태 변화
- `FlowMessageChanged(string)` — 목표/안내 문구 변화

`GameManager`

- `DayCorrectReport` — 정답 보고
- `DayWrongReport` — 오보고
- `DayMissedAnomaly` — 미보고

### 호출용 공개 메서드

| 상황 | 호출 메서드 |
|---|---|
| 브리핑 다음 | `Day1FlowController.BeginBaselineReview()` |
| 감시 시작 | `Day1FlowController.BeginMonitoring()` |
| 배전반 복구 | `Day1FlowController.CompleteEmergencyObjective()` — 일반적으로 `FieldBreakerPanel`이 호출 |
| 제어실 복귀 | `Day1FlowController.ReturnToControlRoom()` — 일반적으로 `FieldControlRoomDoor`가 호출 |

UI는 상태값을 직접 변경하지 않고 위 공개 메서드만 호출한다.

## 5. 시각 연출 권장 타임라인

### 정전 진입

```text
0.0초  경보 문구 / 붉은 플래시
0.1초  CCTV 신호 깨짐
0.4초  완전 암전
0.5초  현장 카메라 노출 및 이동 안내
```

### 배전반 복구

```text
E 유지  게이지 채움, 기계음 점진 증가
완료    짧은 스파크 / 전력 복구음
이후    “제어실로 돌아가십시오” 목표 표시
```

### 제어실 복귀

```text
문 상호작용  암전 또는 문 닫힘 효과
0.2초        CCTV 전원 켜짐 / CRT 부팅음
0.5초        CCTV 화면과 감시 HUD 표시
완료         “감시 업무를 계속합니다” 표시
```

## 6. 빠른 테스트 방법

1. Day1 실행.
2. Enter 두 번으로 감시 시작.
3. 채널을 세 번 전환하고 튜토리얼 이상현상 `D1_A01`을 정답 보고.
4. 튜토리얼 정상화 뒤 `F7`을 눌러 정전 현장 전환을 테스트.
5. 배전반 근처에서 E를 1.5초 유지.
6. 제어실 복귀 문 근처에서 E를 약 0.35초 유지.
7. CCTV 화면 복귀 후 시간이 다시 흐르고 이상현상 생성이 재개되는지 확인.

`F7`은 에디터·개발 빌드 전용 테스트 단축키다. 제출 빌드에서는 끄거나 제거한다.

## 7. 시스템 담당 확인 항목

- Day 종료·평가 화면 데이터와 전환 로직
- 복귀 직후 CCTV 변화 콘텐츠
- 이상현상 추가와 밸런싱
- UI 작업 후 전체 전환 타이밍 통합 검증

## 8. 주의 사항

- `Canvas_CCTV`는 런타임에 독립 생성된다. 현장 전환에서는 시스템이 숨기고, 제어실 복귀에서 다시 켠다.
- 현장 모드 중에는 일반 이상현상 미보고가 발생하면 안 된다.
- `FieldModeRoot` 안의 필드 조명만 현장 전환 중 유지된다.
- 정전/복귀 연출은 상태 전환을 대신하지 않는다. 상태 변경은 시스템이 수행한다.
