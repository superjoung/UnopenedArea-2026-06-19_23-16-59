> 이 문서는 Day3 개발 과정에서 AI가 수행한 작업과 개발자가 직접 판단·제작·검수한 내용을 구분해 기록한다. AI가 제안하거나 코드 초안을 작성한 사실만으로 구현 완료로 표시하지 않으며, Unity Editor와 실제 플레이에서 확인된 결과만 검증 완료로 기록한다.

## 1. 제출용 핵심 요약

### 프로젝트에서 AI를 사용하는 목적

- 기획 문서와 Unity 프로젝트 사이의 데이터 불일치를 빠르게 찾는다.
- 이상현상 ID, 보고 정답, Object ID, Action을 구조적으로 검증한다.
- 반복적인 C# 코드와 데이터 연결 작업의 초안을 작성한다.
- 상태 전환, 입력 잠금, baseline 복원처럼 누락되기 쉬운 예외를 점검한다.
- 플레이 테스트 절차와 회귀 테스트 목록을 작성한다.
- AI의 제안을 그대로 채택하지 않고 개발자가 최종 연출, 아트, 수치, 적용 범위를 결정한다.

### Day3에서 증명할 AI 활용 요소

1. 최신 Google Docs/Sheets와 기존 인수인계 문서의 충돌 분석
2. Day3 보고형 이상현상 데이터와 Unity 에셋의 정합성 검증
3. 미보고 공포와 보고형 이상현상의 책임 분리
4. 손상된 관측 기록 복구 현장 이벤트의 상태 흐름 설계 및 구현 보조
5. 입력 잠금, 타이머 정지, baseline 복원, 1회성 이벤트의 회귀 검증
6. AI 초안과 개발자의 수정·미채택 사례 기록

## 2026-08-09 — Unity MCP 연결 상태 진단

### 개발 목표

- 향후 AI가 Unity Editor 상태, Console, 씬 오브젝트 및 Play Mode를 직접 검증할 수 있도록 Unity MCP 연결 상태를 확인한다.

### AI 수행

- Codex 설정에 `unityMCP = http://127.0.0.1:8080/mcp`가 이미 등록되어 있음을 확인했다.
- localhost의 MCP endpoint가 응답하지 않는 것을 확인했다.
- 프로젝트의 `Packages/manifest.json`에 Unity MCP 패키지가 아직 등록되지 않았음을 확인했다.
- Unity 6 호환 설치 후보로 CoplayDev MCP for Unity의 고정 버전 설치 절차를 조사했다.

### 개발자 판단 및 현재 상태

- 상태: **보류**
- Codex endpoint 설정은 존재하지만 Unity 패키지 설치와 서버 실행이 필요하다.
- 연결 완료 전까지 AI의 Unity 검증은 파일·씬 YAML·코드 정적 분석에 한정한다.
- Unity MCP가 실제 연결된 이후 도구 목록과 ping 결과를 별도로 기록한다.

### 제출 시 주의

- MCP 연결을 시도했다는 사실과 실제로 Unity를 제어해 검증한 사실을 혼동하지 않는다.
- 연결 성공 및 Unity 도구 호출 증거가 생긴 이후에만 “AI가 Unity Editor에서 직접 검증했다”고 기록한다.
