# 미기록 구역 — AI 활용 요소 제안서

작성일: 2026-07-22  
목적: AI 공모전 심사에서 보여 줄 수 있으면서 게임의 핵심 경험을 강화하는 활용안을 선정한다.

## 방향성

AI는 정답 판정처럼 공정성과 재현성이 중요한 규칙을 대신하지 않는다. 대신 아래 세 역할에 집중한다.

1. 제작 가속: 이상현상·대사·사운드·테스트 케이스의 초안을 빠르게 만든다.
2. 플레이 경험 강화: 플레이 기록을 읽고 더 자연스러운 사후 피드백과 난이도 변주를 제공한다.
3. 심사 증명: AI가 어디에 어떤 근거로 쓰였고, 사람이 어떻게 검수했는지 보여 준다.

## 최우선 제안 — P0

### 1. AI 이상현상 콘텐츠 파이프라인

**한 줄 설명**: 기획자가 장소·기준 상태·금지 조건을 입력하면 AI가 이상현상 후보, 보고 정답, 연출 문구, 검수 항목을 생성하고 사람이 채택한다.

**게임 적용**

- 입력 예시: `연구실 복도 / 휠체어, 문, 초상화가 기준 상태 / 지나친 점프스케어 금지 / Day 1 난이도`.
- 출력 예시: `휠체어 위치 변경`, `문 스프라이트 변화`, `초상화 회전`과 각각의 `[구역]+[대상]+[유형]` 정답.
- 채택한 결과만 `AnomalyDefinition` 에셋으로 등록한다. 런타임 정답 판정은 기존의 결정적 규칙을 유지한다.

**심사 포인트**

- AI가 만든 초안 → 기획자 검수 → 실제 에셋 반영의 과정을 한 화면으로 제시할 수 있다.
- 콘텐츠 양산뿐 아니라 보고 정답·오답 가능성·선행조건까지 함께 검수하는 점이 강점이다.

**구현 난이도**: 낮음. 우선은 프롬프트 템플릿과 Markdown/JSON 결과물로 시작한다.

### 2. AI 근무 기록 분석관

**한 줄 설명**: 하루가 끝나면 플레이 로그를 AI가 읽고, 관찰 습관·놓친 구역·오보고 경향을 ‘감시관 평가서’ 형식으로 요약한다.

**게임 적용**

- 입력: 채널 체류 시간, 보고 이력, 미보고 이상현상, 정답률, 긴급 출동 여부.
- 출력: “연구실 복도의 확인 간격이 길었습니다. 다음 근무에서는 2번 채널을 먼저 확인하십시오.” 같은 2~3문장 평가.
- UI 담당은 Day 종료 패널에 평가 카드 1장과 다음 날 팁 1줄을 표시한다.

**심사 포인트**

- 단순 챗봇이 아니라, 실제 플레이 데이터에 반응하는 개인화된 게임 경험이다.
- 로그 원문과 AI 요약을 나란히 보여 주면 신뢰성도 증명할 수 있다.

**구현 난이도**: 중간. API가 없을 때는 사전 생성된 예시 평가서로 데모하고, API 연결은 선택 사항으로 둔다.

### 3. AI 활용 증명 보드

**한 줄 설명**: 개발 중 AI가 제안한 콘텐츠와 실제 채택·수정·미채택 결과를 타임라인으로 공개한다.

**게임/발표 적용**

- 이미 작성 중인 `AI_활용_개발_타임라인.md`를 기반으로 한다.
- 발표 슬라이드 또는 게임 내 개발 기록 메뉴에 `AI 제안`, `사람의 검토`, `최종 반영`을 3단으로 표시한다.
- 예: 성공 보고 정상화 연출은 AI가 흐름을 구조화했고, 최종 노이즈 길이·연출 강도는 팀이 결정했다고 기록한다.

**심사 포인트**

- AI를 단순 사용했다는 주장보다, 책임 있는 협업 과정이 증명된다.

**구현 난이도**: 낮음. 현재 문서 자산을 발표용으로 재구성하면 된다.

## 확장 제안 — P1

### 4. AI 적응형 감시 난이도 디렉터

플레이어의 최근 미보고·오보고·채널 이동 패턴을 기반으로 다음 이상현상의 간격, 위치 분산, 복합도를 조절한다.

- 쉬운 방향: 미보고가 이어지면 발생 간격을 늘리고, 자주 보지 않는 구역부터 단순 이상현상을 배치.
- 어려운 방향: 안정적으로 해결하면 다른 구역에 연속 이상현상, 시각적으로 유사한 대상, 짧은 유지 시간을 배치.
- 안전장치: AI가 직접 수치를 무제한으로 결정하지 않고 `쉬움/표준/긴장` 세 난이도 프리셋 중 하나만 선택한다.

### 5. AI 사건 보고서·라디오 대사 생성

긴급 출동, Day 종료, 새로운 규칙 발견 시 상황에 맞는 짧은 문서를 생성한다.

- 공포 톤과 세계관 용어를 고정한 프롬프트를 사용한다.
- 출시 빌드에는 검수한 대사 풀을 저장해 사용하고, 실시간 생성은 데모 기능으로 제한한다.
- UI·이펙트 담당은 문서 출력 애니메이션, 타자기 효과, 라디오 자막을 제작한다.

### 6. AI 기반 플레이테스트 리포트

테스트 영상 또는 플레이 로그를 넣으면 AI가 ‘어디에서 이상현상을 놓쳤는지’, ‘보고 UI에서 어떤 선택이 혼동됐는지’를 요약한다.

- 결과를 버그가 아닌 관찰 가설로 취급하고, 사람이 재현 테스트로 확정한다.
- 심사 시 AI가 디자인 의사결정을 돕는 모습을 보여 주기 좋다.

## 실험 제안 — P2

### 7. CCTV 장면 차이 설명 보조

두 CCTV 스크린샷의 차이를 AI가 후보 문장으로 제시하는 ‘관제 보조 장비’ 콘셉트다.

- 플레이어에게 정답을 주지 않도록 “문 주변 확인 권장”처럼 모호한 힌트만 제공한다.
- 단서 사용 횟수나 점수 페널티를 둬 관찰 게임의 본질을 지킨다.
- 실제 비전 모델 연동 전에는 지정된 이상현상 데이터에서 힌트 문구를 꺼내는 방식으로 프로토타입 가능.

### 8. AI 음성·사운드 변주

무전 잡음, 안내 방송, 정전 복구 알림의 변주를 생성한다.

- 저작권·사용 허가가 명확한 도구와 결과물만 사용한다.
- 실시간 생성 대신 검수한 오디오 파일을 번들에 포함한다.

## 권장 데모 구성

3분 내 시연은 다음 흐름이 가장 명확하다.

1. Day 1에서 AI 검수 기반 이상현상 하나를 발견·정답 보고한다.
2. 성공 노이즈와 기준 상태 복구를 보여 준다.
3. Day 종료 후 AI 근무 기록 분석관의 평가 카드가 등장한다.
4. 발표 화면에서 ‘AI 초안 → 팀 검수 → 게임 반영’ 타임라인과 로그 근거를 보여 준다.

## 주의 사항

- 공모전 규정상 AI 도구·모델·생성물의 권리와 공개 의무를 먼저 확인한다.
- 플레이어의 입력·로그를 외부 API로 보낼 경우, 수집 항목과 목적을 명시하고 개인식별정보는 포함하지 않는다.
- 네트워크/API 장애가 나도 게임이 진행되도록 AI 기능은 항상 사전 제작 데이터 또는 규칙 기반 폴백을 제공한다.
- AI 출력은 반드시 팀이 검수한다. 특히 보고 정답, 공포 표현 수위, 저작권·유사성은 자동 반영하지 않는다.
