## 1. 현재 상태 요약

- Day 1은 타이틀·전화·대사·CCTV 감시·보고·정전·현장 배전반 복구·제어실 복귀·성공/실패·다음 일차 전환까지 한 사이클을 실행할 수 있다.
- 공용 카메라·UI·사운드·메인룸 시스템은 `CommonRoot` 프리팹으로 분리했고, 일차별 데이터와 연출은 각 `DayContentRoot`와 `DayDefinition`에서 관리한다.
- Day 2는 연구실 복도와 치료실을 중심으로 `D2_A01~A10` 이상현상 데이터 및 프리팹 대상 연결을 구성했다. A11은 Definition만 남긴 미완성 예약 항목이다.
- Day 2 첫 이상현상은 감시 시작 20초 뒤 `D2_A01`로 고정된다. 그 뒤에는 15~25초 랜덤 간격으로 A01~A10 중 하나가 나오며, 직전 현상은 즉시 연속 선택되지 않는다.
- Day 2 미보고 허용 횟수는 4회다. 1~3회는 `D2_NR01~03` 접근 연출, 4회째는 기존 최종 실패 흐름을 사용한다.

```text
Day 2 씬 페이드 인
→ 4초 후 전화 수신
→ 전화 대사
→ CCTV 감시 시작
→ 20초 후 D2_A01 고정 발생
→ 정답/미보고 처리
→ 15~25초 랜덤 대기
→ 다음 이상현상
→ 근무 성공 또는 오보고/미보고 한도 초과 실패
```

## 3. 이상현상 실행 구조

`AnomalyDefinition`의 액션은 역할에 따라 다음처럼 사용한다.

- 단순 등장/퇴장: `SetActive`
- 이미지 교체: `ChangeSprite`
- 위치 이동: `MoveToLocalPosition`
- 회전: `SetLocalEulerAngles`
- 시간축 연출: `PlayPresentation`
- Animator 활성 상태 직접 제어가 꼭 필요한 예외: `SetAnimatorEnabled`

`PlayPresentation`은 Definition에 프레임을 직접 넣지 않는다. 대상 프리팹의 `AnomalyPresentationController`에 동작을 만들고, Definition은 `Presentation ID`만 호출한다. 현재 지원 모드는 좌우 왕복 이동과 Animator State 재생이다. CCTV 구역이 화면에 들어왔을 때 시작하도록 설정할 수 있고, 정상화 시 실행 중인 연출과 Animator 상태도 기준 상태로 복구된다.

## 6. Day 2 미보고 연출

`Day2MissedPresentationController`가 미보고 누적 횟수를 받아 런타임에 생성된 치료실 프리팹을 찾는다. 따라서 씬에서 프리팹 내부 오브젝트를 직접 할당하지 않는다.

| 단계 | 기획 ID | 실행 내용 | 대상/시간 |
|---|---|---|---|
| 1회 | `D2_NR01` | 커튼 뒤 손이 화면 가로 중앙에 오면 Q/E와 패닝을 잠그고 애니메이션 재생 후 숨김 | `OBJ_TREAT_CURTAIN_HAND_01`, 2초 |
| 2회 | `D2_NR02` | 큰 얼굴을 CCTV 렌더 카메라 피드 안에 표시해 CRT 효과와 함께 출력 | 3초 유지 + 0.5초 페이드 |
| 3회 | `D2_NR03` | 침대 아래 인물이 화면 가로 중앙에 오면 입력을 잠그고 애니메이션 재생 후 숨김 | `OBJ_TREAT_UNDERBED_PERSON_01`, 2초 |

NR02의 `FaceImg`는 얼굴 스프라이트를 제공하는 비활성 소스 오브젝트다. 실행 시 별도의 SpriteRenderer를 실제 `CCTVCamera` 아래에 만들고 RenderTexture에 함께 찍기 때문에 Canvas sibling 순서를 바꾸지 않는다.

## 7. Unity Inspector 확인 사항

### Day 2 씬

- `CommonRoot`가 프리팹 인스턴스로 존재하는지 확인한다.
- `Day2ContentRoot`의 Day 런타임이 `Day2Definition.asset`을 참조하는지 확인한다.
- `Day2MissedPresentationController`의 얼굴 소스 이름은 `FaceImg`, RawImage 검색 이름은 `RawImage_CCTVScreen`이다.
- `FaceImg`에는 사용할 얼굴 스프라이트를 넣되 평소에는 비활성화한다.
- 다음 일차 타이틀 건너뛰기 흐름은 씬 페이드 인 뒤 4초 후 전화가 울리도록 설정되어 있다.

### 연구실 복도 프리팹

- 일반 직원: `OBJ_D2_LAB_STAFF_NORMAL`
- 복도 끝 직원: `OBJ_D2_LAB_STAFF_BACK`
- 일반 직원에 `Glide`, `LookBack` Presentation ID가 중복 없이 존재하는지 확인한다.
- 마지막 프레임 고정 애니메이션은 Animation Clip의 `Loop Time`을 끈다.

### 치료실 프리팹

- 환자: `OBJ_TREAT_PATIENT_01`, `OBJ_TREAT_PATIENT_02`
- 커튼 애니메이션: `OBJ_TREAT_CURTAIN_02` / `CurtainBreathing`
- 침대 애니메이션: `OBJ_TREAT_BED_02` / `BedIndentation`
- 미보고 오브젝트: `OBJ_TREAT_CURTAIN_HAND_01`, `OBJ_TREAT_UNDERBED_PERSON_01`
- 환자와 미보고 연출 오브젝트는 정상 상태에서 비활성인지 확인한다.

## 8. 인계 전 필수 플레이 테스트

1. Day 1 성공 후 Day 2로 전환했을 때 Day 1 타이틀·튜토리얼·대사가 반복되지 않는지 확인한다.
2. Day 2 씬 페이드가 끝난 뒤 정확히 4초 후 전화가 울리는지 확인한다.
3. CCTV 감시 시작 20초 뒤 첫 현상이 반드시 `D2_A01`인지 확인한다.
4. A01을 처리하지 않아도 활성 시간 종료 및 미보고 처리 뒤 다음 랜덤 대기가 시작되는지 확인한다.
5. 실행 풀의 `D2_A01~A10`을 하나씩 강제 실행해 표시, 보고 정답, 정상화 후 원상복구를 확인한다.
6. NR01과 NR03이 치료실 화면 가로 중앙에서 2초 동안 입력을 잠그고 한 번만 재생되는지 확인한다.
7. NR02 얼굴이 CCTV 외부 UI가 아니라 CCTV 화면 안에 나오고 CRT 노이즈의 영향을 받는지 확인한다.
8. 4번째 미보고에서 최종 실패하고, 보고판과 입력이 정상적으로 정리되는지 확인한다.
9. 씬 재시작/F9 전체 초기화 뒤 미보고 횟수, 재생 완료 플래그, Animator가 초기화되는지 확인한다.
10. 빌드에서 CCTV CRT 셰이더와 신규 애니메이션 Controller가 누락되지 않는지 확인한다.

## 9. 남은 작업과 알려진 위험

### P0

- NR02 얼굴의 최신 렌더 경로는 코드 정적 검토만 완료했고 Unity 플레이 모드 최종 확인이 필요하다. 얼굴이 안 보이거나 셰이더 앞에 뜨면 Canvas 순서를 다시 바꾸지 말고 `CCTVScreenEffectController.WorldCamera`, CCTVCamera Culling Mask, SpriteRenderer Layer/Sorting을 먼저 확인한다.
- `D2_A11`의 실제 액션과 최종 스프라이트를 연결해야 한다.
- `D2_A01~A10` 전체 강제 실행 회귀 테스트가 필요하다.

### P1

- NR01/NR03 전용 사운드와 NR02 얼굴 노출 타이밍을 기존 미보고 신호 유실 노이즈에 맞춰 조정한다.
- Day 2 전화 대사 본문과 인물별 텍스트는 콘텐츠 담당이 입력한다.
- 300초 근무, 15~25초 생성 간격, 20초 활성 시간은 실제 플레이 후 밸런싱한다.

### 버전 관리 주의

- 이번 작업에는 신규 애니메이션·캐릭터/오브젝트 아트, `CommonRoot` 프리팹, Day 1/2 씬의 대규모 직렬화 변경이 포함되어 있다. 씬을 Unity에서 다시 저장한 뒤 머지하는 편이 안전하다.
- 최신 기획서는 기존 `이상현상 콘텐츠 기획서_v1.0.0.xlsx`를 `(1)` 파일로 교체한 상태다. 추적 중이던 임시 잠금 파일 `~$...xlsx`는 삭제 상태를 반영하고 다시 추가하지 않는다.

## 11. 인계 기준

- 시스템·콘텐츠 담당은 Definition, Object ID, 프리팹 기준 상태, 스케줄과 정상화를 관리한다.
- UI·이펙트 담당은 기존 공개 이벤트와 Inspector 시간값을 사용하며 런타임 상태를 직접 수정하지 않는다.
- 신규 특수 연출은 Definition에 일회성 코드를 추가하기보다 프리팹의 `AnomalyPresentationController` 또는 일차 전용 컨트롤러로 분리한다.
- 테스트 결과가 확인되지 않은 항목은 완료로 간주하지 않고 위 P0 목록에 남긴다.
