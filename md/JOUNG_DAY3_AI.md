### 1.3 CAM-00 관련 처리

기존 `Day3_개발_인수인계서.md`에 있는 아래 요소는 최신 Day3 현장이동 본문과 최신 스프레드시트의 필수 구현 목록에서 확인되지 않았다.

- CAM-00에서 실제 플레이어보다 약 12초 앞선 영상 표시
- 실제 플레이어보다 먼저 고개를 돌리는 영상
- 귀환 전후 제어실 의자 점유 장면
- `CAM00_VIEWED`를 Day3 현장 완료 필수 조건으로 사용하는 흐름

따라서 이 항목들은 현재 Day3 P0/P1 구현에 자동 포함하지 않는다. 추후 사용자가 별도로 유지 또는 재도입을 지시할 때만 독립적인 스토리 연출로 설계한다.

### 3.2 콘텐츠 배치 순서

각 항목은 다음 순서로 작업한다.

1. 해당 Area 프리팹의 정상 배치를 먼저 완성한다.
2. 오브젝트에 최신 `target_object_id`를 연결한다.
3. baseline 캡처 전에 정상 활성 상태, 스프라이트, 위치, 회전, Animator 상태를 확인한다.
4. `AnomalyDefinition`에 Area, Report Target, Report Type을 입력한다.
5. 정적 변화는 기존 Action을 사용하고 시간축 변화는 Presentation으로 분리한다.
6. 강제 발생으로 표시를 확인한다.
7. 정확 보고 후 노이즈 중 baseline 복원을 확인한다.
8. 미보고 만료, 씬 재시작, F9 초기화에서도 오브젝트와 Animator가 복원되는지 확인한다.
9. 검증을 통과한 Definition만 Day3 랜덤 풀에 포함한다.

공통 규칙:

- `report_required = false`다.
- 보고 패널의 구역·대상·유형 후보에 추가하지 않는다.
- 이 연출 자체가 오보고 또는 미보고 카운트를 증가시키면 안 된다.
- 모두 `trigger_once = true`다. 기본 구현은 한 Day 세션에 각 이벤트 최대 1회로 해석한다.
- D3_NR01은 CCTV RenderTexture 내부에서 표시하여 CRT 효과와 함께 보이게 한다.
- D3_NR02는 화면 상단 viewport를 가로지르는 움직임으로 구성한다.
- D3_NR03은 일반 월드 인물이 아니라 유리 반사면에만 나타나야 한다.
- 보고형 이상현상, 성공 정상화, 채널 전환 노이즈, 최종 실패 연출과 동시에 겹쳐 판별을 방해하면 안 된다.

### 4.1 권장 런타임 연결 방식

아래는 최신 표를 현재 프로젝트 구조에 연결하기 위한 구현 권장안이다. 표에 없는 정책을 제품 규칙으로 하드코딩하지 말고 Inspector 또는 Day3 전용 설정으로 둔다.

```text
일반 이상현상 미보고 확정
→ 기존 미보고 카운트 처리
→ Day3 미보고 공포 후보 활성화 요청
→ 아직 실행하지 않은 후보 중 현재/대상 구역에 맞는 항목 준비
→ TimedScreenFlash 또는 OnObjectEnterViewport 조건 대기
→ 지정 확률을 한 번만 판정
→ 성공 시 입력 충돌 여부 확인 후 연출 실행
→ 실행 완료 플래그 저장
→ 보고형 이상현상 스케줄은 기존 안정 구간 뒤 별도로 재개
```

확정이 필요한 부분:

- 미보고 횟수별로 NR01→NR02→NR03을 고정할지, 실제로 랜덤 후보를 추첨할지
- 확률 판정을 미보고 등록 시 할지, viewport 조건 충족 시 할지
- 확률 실패 시 같은 Day에서 다시 판정할지

스프레드시트에는 `미보고 랜덤`, 개별 확률, `trigger_once=true`가 정의되어 있으므로 기본 권장은 조건 충족 시 한 번 판정하고, 성공 실행된 이벤트만 완료 처리하는 방식이다.

## 5. Day3 현장이동 이벤트 상세

### 5.1 진입 조건

- 일차 진행률 65% 이상
- CCTV 또는 기록 시스템 손상 경고 발생
- 보고 성공/실패 연출, 채널 전환, 다른 필수 UI가 진행 중이지 않을 것
- 현장 맵, 목표 오브젝트, 조명, 플레이어 입력이 준비되어 있을 것

### 5.2 목표 오브젝트

서버실의 기록 단말 또는 서버 랙을 사용한다.

필수 상태:

- 조명 범위 밖: 기본 상태
- 조명 범위 안: 외곽선 또는 강조
- 상호작용 거리 안: E키 안내
- 화면 열림: 이동·조명·다른 상호작용 잠금
- 홀드 진행: 진행률 표시
- 홀드 취소: 진행률 초기화가 기본이며 필요 시 Inspector 옵션으로 점진 감소
- 완료: 서버 랙 작동등 변화, 완료 메시지, 기록 일부 표시

### 5.3 입력 순서

1. E 클릭: 기록 단말 또는 서버 화면 열기
2. 복구 대상 기록 확인
3. E 홀드: 기록 복구
4. 완료 후 손상 기록 일부 확인
5. 팝업 닫기 또는 완료 확인
6. 복귀 목표 표시

홀드 중 이동하거나 범위를 벗어나거나 E를 놓으면 취소한다. 팝업, 모드 전환, 강제 연출 중에는 현장 입력을 초기화하고 잠근다.

### 5.4 필수 화면 요소

- 기록 단말 또는 서버 화면
- 복구 대상 기록 표시
- E 홀드 진행률
- 서버 랙 작동등 변화
- 복구 완료 메시지
- 복구된 기록 일부
- 제어실 복귀 목표

### 5.5 완료 플래그

최신 문서는 플래그의 역할은 확정하지만 문자열 이름은 고정하지 않는다. 기존 코드와 충돌하지 않는 하나의 이름을 선택하고 전 구간에서 통일한다.

권장 이름:

- `D3_OBSERVATION_RECORD_RESTORED`

이 플래그는 다음 용도로만 사용한다.

- 현장 목표 완료 판정
- 후속 CCTV 기록 또는 스토리 정보 활성화
- D3_F01 복귀 연출 허용
- 중복 복구 방지

기존 `SERVER_REBOOTED`가 이미 저장 데이터에 사용 중이라면 즉시 삭제하지 말고 참조 위치를 조사한 뒤 마이그레이션 또는 호환 별칭 여부를 결정한다.

## 6. 현장이동 공포 풀

`07_현장이동_이상현상` 최신 기준:

| ID | 위치 | 이벤트 | 정책 | 확률 | 최대/방문 | 비고 |
|---|---|---|---|---:|---:|---|
| `D3_FA01` | 서버실 | 서버 화면 얼굴 노이즈 | `RANDOM` | 0.30 | 1 | D3_NR01 리소스 재사용 |

랜덤 공포 공통 규칙:

- `occurrencePolicy = RANDOM`만 랜덤 풀에 넣는다.
- 같은 이벤트는 한 번의 현장이동에서 기본 1회만 발생한다.
- 기본 쿨다운은 30초다.
- 목표 오브젝트와 혼동되는 외곽선을 사용하지 않는다.
- 보고·오보고·미보고·실패 카운트에 연결하지 않는다.
- 스토리 핵심 단서는 랜덤 공포 풀에 넣지 않는다.

### 6.1 D3_F01 필수 규칙

- `D3_F01`은 랜덤 추첨 대상이 아니다.
- 손상 기록 복구가 끝난 후 제어실로 복귀하는 지정 구간에서 실행한다.
- 이벤트 타입: `VisionAngleRush`
- 트리거: `RandomOnLookAngle`
- 대상: `OBJ_FIELD_D3_OBSERVER_RUSH`
- 필요한 시야 각도: 25도
- 시야 끝 거리: 8
- 이동 시간: 0.2초
- 사운드: `SFX_FIELD_RUSH`
- 한 현장 방문 최대 1회
- 팝업, 홀드 처리, 모드 전환 중에는 실행하지 않는다.
- 마지막 프레임 또는 짧은 시각 단서로 O-06 존재를 전달한다.
- 플레이어 피해, 즉사, 전투, 지속 추격 AI로 확장하지 않는다.
